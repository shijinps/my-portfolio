01
Design & Topology Planning

Enterprise Architecture Blueprint in Draw.io (diagrams.net)

Prior to ordering and unboxing expensive physical hardware, a complete architectural blueprint was drafted using the open-source tool Draw.io (app.diagrams.net). This blueprint served as the definitive technical source of truth for all stakeholders, cabling technicians, and network administrators.

WAN Edge & Perimeter Security

  • Dual ISP Connections: Leased line termination for primary (AIRTEL) and secondary (TATA) carriers through dedicated demarcation switch.
  • FortiGate HA Cluster: Active-Passive firewall pair (FGT-FW-1 & FGT-FW-2) with dual heartbeat sync links for stateful session pickup.
  • Redundant WAN Handoffs: Independent links from each ISP to both firewalls, preventing upstream carrier single points of failure.

Core & Access Switching Hierarchy

  • Dual Arista Core Layer: DCN-CORE-SW-1 and DCN-CORE-SW-2 joined via high-speed Multi-Chassis Link Aggregation (MLAG).
  • Dual-Homed Uplinks: 6 Access Switches (DCN-ACC-SWITCH-1 through 6) and 2 Access Point switches each wired with dual uplinks split across Core 1 and Core 2.
  • Precision Port Matrix: Exact port designations, SFP+ optical assignments, transceiver specifications, and VLAN subnets visually documented.
02
Virtual Environment Emulation

Complete Infrastructure Emulation in GNS3

To validate the Draw.io blueprint under real network operating conditions, the entire campus topology was replicated inside GNS3 (Graphical Network Simulator-3). By running actual virtualized network operating system images, this sandbox allowed full functional verification without touching physical hardware or risking live downtime.

Virtual Appliances

Deployed Fortinet FortiOS VM appliances for firewall routing and Arista vEOS virtual switches running actual Extensible Operating System (EOS) command line.

Virtual Cabling

Wired virtual ethernet interfaces mimicking real-world SFP+ transceivers, LACP trunks, FortiGate HA heartbeat links, and ISP upstream feeds.

Test Endpoints

Attached VPCS (Virtual PC Simulator) and Linux test nodes across all simulated access switches to verify end-to-end routing, DHCP leasing, and packet flow.

03
Protocol Staging

Configuration Demonstration & Multi-Chassis HA Validation

With the GNS3 topology online, all enterprise configuration sets were staged, demonstrated, and calibrated. This ensured zero syntax errors, protocol mismatches, or spanning tree loops before applying commands to the production Arista and Fortinet hardware.

# Arista vEOS MLAG & LACP Port-Channel Verification:
mlag configuration: domain-id CAMPUS-CORE | heartbeat-interval 1000ms
interface Port-Channel10 (MLAG Peer-Link): active-full, 2x 10G interfaces bonded
interface Port-Channel1..6 (Access Downlinks): MLAG active-active to downstream switches
# FortiGate Active-Passive Clustering (FGCP):
config system ha: group-id 50 | mode a-p | hbdev port10 50 port9 50
session-pickup enable | session-pickup-delay disable | ha-direct enable
04
Chaos & Stress Testing

Simulated Disaster Recovery & Zero-Packet-Loss Failover

In GNS3, extreme failure scenarios were systematically induced while running high-frequency ICMP pings and active TCP streams across the virtual topology:

  • Simulated Uplink Link Cut: Disconnected one uplink leg from Access Switch 1. LACP dynamically routed 100% of packets via the surviving link to Core 2 with 0 packet drops.
  • Simulated Core Switch Crash: Force-halted Core Switch 1. MLAG peer failover seamlessly diverted all campus access traffic across Core Switch 2 within milliseconds.
  • Simulated Primary ISP Failure: Severed the Airtel WAN connection. FortiGate SD-WAN health checks immediately shifted outbound default routing to Tata leased line without session drops.
